### 方案 B 的实现要点

- **设备节点按「同种设备 × N 台」聚合**：N 台共用生产目标和缓冲区，每步按 N 倍推进。矿脉独立为资源节点；采矿机拼在矿脉旁开采，熔炉和制造台在建成后选择配方。
- **固定步长**：模拟 10 次/秒，和渲染帧率无关。
- **整数运算**：物品数量用整数；生产进度用「已经过的步数」计数，不用浮点秒数，避免长时间运行后误差累积、离线和在线结果对不上。
- **物品用数字 ID**：物品和配方在启动时编号，缓冲区是定长槽位，方便以后改成 TypedArray（结构数组）存储。
- **连线即时送达、按吞吐量限流**：先不模拟「物品在带子上走的时间」，只限制每步最多搬多少。
- **分配要公平**：一个输出接多个下游时，按轮询分配，起点每步轮换，否则永远是第一条连线吃饱。
- **离线结算：暂不做（2026-10-28 决定）**。关掉页面就暂停，回来从存档时的状态继续。以后要做时的思路：在 Web Worker 里按同样步长快进，检测到稳态（连续若干步库存变化量相同）后线性外推剩余时间。现在保持「固定步长 + 整数运算」，就是为以后加这一步留好条件。
- **模拟放进 Web Worker**：主线程只接收每颗行星的快照，降频更新界面（DSPONLINE 的性能报告证明这一点很关键）。

### 系统顺序（方案 B）

电力（算满足率）→ 生产（消耗输入缓冲、推进进度、产出到输出缓冲，缺电按比例减速）→ 运输（沿连线搬运，轮询分配）→ 科研 → 戴森 → 解锁检查

## 技术栈

- **React + React Flow**（核心库 MIT，可商用）负责无限画布：拖动缩放、节点拖拽、端口连线、框选、小地图、吸附
  - 节点 node = 配方/资源/仓库等方块；连线 edge = 物流；端口 handle = 输入/输出物品
- **游戏状态不放进 React Flow**，放在单独的状态里（如 zustand），画布只负责显示和接收操作
- 控制节点数量：一个节点 = N 台同种建筑，支持模块折叠；开启只渲染可见区域
- UI 风格：用 ui-ux-pro-max skill，初步方向「HUD / 科幻界面」、深色配色、蓝色强调色（搜索词需用英文）

## ECS 架构

采用 **轻量自写 ECS**（TypeScript 普通对象），不用 bitECS 等重型库：实体 = ID，组件 = 按 ID 存的数据表，系统 = 按固定顺序调用的函数。

理由：当前原型实体规模小，核心是按固定步长遍历生产设施和连线，普通 TypeScript 数据表已经足够；先保持实现简单，不引入额外 ECS 库。

先例：Mozilla Hubs（bitECS）、ECSY、Koota（pmndrs）、miniplex、Becsy。

### 组件（MVP 控制在 10 个以内）

| 组件 | 挂在哪些实体上 | 内容 |
|---|---|---|
| Position | 所有画布节点 | x、y、所在行星 |
| Resource | 矿脉节点 | 矿产类型、剩余储量 |
| Extractor | 采矿机节点 | 台数、采矿进度、吸附矿脉 ID 和边缘 |
| Storage | 仓库节点 | 各物品库存、上限 |
| PowerUse / PowerGen | 用电/发电建筑 | 功率 |
| Link | 连线（连线也是实体） | 起止节点与端口、物品 |
| Buffer | 配方、仓库、研究节点 | 输入缓冲、输出缓冲（各物品数量、上限） |
| Crafter | 生产设备节点 | 设备类型、可切换的配方 ID、台数、进度、生产状态 |
| Flow | 连线、节点 | 最近一段时间的平均速率（只用于显示） |

系统执行顺序见上方「方案 B」一节。

### 注意事项

1. **数据只存一份**：画布节点由 ECS 数据推导；拖动只改 Position，不要画布和 ECS 双向同步
2. **控制刷新频率**：每个节点组件只订阅自己的数据，统计面板降频刷新
3. **结果确定性**：固定系统顺序、固定时间步长、带种子随机数（保证离线结算与在线一致、可复现）
4. **稳定 ID**：自增或 UUID，不复用 ID（bitECS 默认会回收）
5. **连线成环**：如 X 射线裂解用氢产氢；方案 B 逐步搬运天然能处理环，但要给回路一个初始库存，否则会卡在 0
6. **存档带版本号**，准备迁移函数
7. **不过度抽象**

## P0 原型实现进度（2026-10-28）

- 已接入 React + React Flow 画布，矿脉、采矿机、生产设备、仓库节点，以及建造目录、拖动、缩放、小地图、连线和删除。
- 节点展示缓冲库存、台数、生产状态和实际产量；可调台数，连线展示物品流量。也可在节点详情里选择下游建立连接。
- 首次打开默认载入蓝矩阵示例，目标稳定产量 120 个/分钟。按用户要求删除画布顶部的标题、说明、设施计数、矩阵统计卡和添加示例工具条；空画布仍可载入示例。
- 支持暂停、1/2/5 倍速、本地自动保存和刷新恢复；隐藏页面时暂停并保存，回到页面不补算离线时间。
- UI 采用 ui-ux-pro-max 的 HUD / Sci-Fi 方向：深蓝背景、蓝色强调色、文字和颜色共同表达状态，窄屏使用可收起的建造目录。
- **当前实现边界**：沿用已有主线程模拟循环，Web Worker 尚未迁移；没有电力、科研解锁、多行星、戴森工程与离线结算。缓冲区目前使用数字 ID 为键的普通对象。
- 原型自由建造，不消耗建筑材料。运行方法和操作说明见根目录 README.md。

### 矿脉和设备分离（2026-10-28）

- 铁矿、铜矿是独立矿脉；采矿机独立建造，拖到矿脉任意空闲边缘后吸附，拖离即停止。每条边可接入一组设备，储量由矿脉统一扣除。
- 电弧熔炉是同一种设备，铁块、铜块、磁铁是其生产目标；制造台同理。建造目录只列设备，节点内选择配方。
- 切换目标退回未完成生产的原料，旧原料和产物保留在输出缓冲，供物流回收；清理不兼容的连线。
- 存档升级到 v2，自动把旧采矿节点拆成矿脉与设备，保留原设备 ID、库存、连线、配方及进度。
